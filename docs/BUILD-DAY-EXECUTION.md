# Build-Day Execution Plan

Status: aggressive competition execution plan.

Published build window: 9:30 AM to 5:00 PM.

Goal:
Ship a defensible working product plus visible software factory evidence from a blank implementation repo.

This plan assumes pre-event planning/specification is allowed and implementation code begins at kickoff.

## Operating rule

Do not optimize for maximum feature count.

Optimize for:

```text
working vertical slice
+ visible factory machinery
+ evidence
+ one or two surprising advanced capabilities
```

Then stretch aggressively.

## 9:30–9:45 — Baseline and bootstrap

Actions:

- verify blank repo
- record kickoff evidence
- run Conditor/bootstrap
- install/initialize permitted Echelon components
- create solution/projects
- first commit
- start ROS work
- Praxis baseline
- CI skeleton

Exit criteria:

- clean build
- repo provenance captured
- factory visible

## 9:45–10:30 — Semantic kernel

Implement:

- identities
- essential entities
- essential commands/events
- decide/evolve
- semantic registry
- core lifecycle tests

Minimum commands:

- StartInvestigation
- RecordObservation
- RecordHypothesis
- AdmitEvidence
- RelateEvidence
- IdentifyUnknown
- RecordContradiction
- FalsifyHypothesis
- RecordCausalAssertion
- ConfirmCause
- RecordCorrectiveAction
- RecordVerification
- ResolveInvestigation

Exit criteria:

- property/state tests pass
- illegal ConfirmCause demonstrably blocked

## 10:30–11:15 — Local workspace

Implement:

- Investigation Start
- Workspace
- hypothesis comparison
- evidence capture
- blockers/unknowns
- next action
- persistence status

Use Forma/Limen.

Exit criteria:

- complete manual local investigation possible
- iPad layout usable

## 11:15–12:00 — Local durability + GitHub provider

Implement:

- local durable state
- queued commands
- GitHub load/append
- optimistic concurrency
- offline indicator
- basic recovery

Exit criteria:

- refresh survives
- remote sync works
- pending state honest

## 12:00–12:45 — AI proposal loop

Implement:

- context builder
- one provider
- structured hypothesis/unknown/action proposals
- proof-carrying evidence refs
- accept/reject
- challenge mode

Exit criteria:

- AI cannot mutate raw state
- malformed proposal rejected
- challenge finds alternative/falsifier

## 12:45–1:15 — Eat while validation runs

Run:

- semantic compiler checks
- property tests
- accessibility scan
- prompt-injection fixtures
- first proof bundle snapshot

Fix critical drift.

## 1:15–2:00 — Investigation loop completion

Implement:

- prediction
- action/experiment

- falsification
- causal assertion
- corrective action
- verification
- resolution gate
- Folio interim/final report

Exit criteria:

- end-to-end demo path works
- implemented != verified visibly

## 2:00–2:45 — First signature advanced feature

Priority:
Time travel + semantic diff + "what changed my mind?"

Why:
Uses event architecture already built and produces a unique visible result.

Exit criteria:

- scrub to historical state
- semantic diff
- explanation references actual events

## 2:45–3:30 — Second signature advanced feature

Choose based on current stability:

Preferred:

- Generator

Alternative:
Counterfactual sandbox.

Do not attempt both if core stability suffers.

Exit criteria:

- frozen source
- structured outputs
- disagreement visible
- no state corruption

## 3:30–4:00 — Factory/proof view

Implement:

- requirements/test coverage summary
- ROS current/completed work

- Aegis faults
- semantic contract completeness
- commit/deploy status

Generate proof bundle.

Exit criteria:

- every displayed metric real
- missing evidence visible

## 4:00–4:25 — Security/resilience demonstration

Verify:

- prompt injection fixture
- tool capability denial if tool gateway implemented
- no secrets
- offline workflow
- stale conflict

Fix only critical issues.

## 4:25–4:40 — Demo reset/replay/spectator

Prepare:

- canonical demo investigation reset
- deterministic replay
- judge explorer mode
- report snapshot
- fallback recorded multi-agent run if live model latency fails

## 4:40–4:55 — Final validation

Run:

- build
- tests
- semantic compiler
- smoke
- accessibility critical checks
- demo health
- proof bundle
- deploy

No new features after 4:45 unless trivial and isolated.

## 4:55–5:00 — Freeze submission

- tag/final commit
- capture final build/deployment identity
- issue proof bundle
- verify demo URL/local fallback
- stop changes

## Stretch path if ahead

Order:

1. Counterfactual sandbox
2. Evidence dependency graph
3. bounded autonomous read-only investigation
4. local WASM artifact diff/hash
5. investigation replay
6. research tournament
7. self-diagnostic factory investigation

## Recovery path if behind

Preserve in this order:

1. typed kernel
2. policy/blockers
3. usable workspace
4. local persistence
5. AI proposal loop
6. GitHub sync
7. cause/correction/verification
8. proof/factory view

Cut in this order:

1. fancy animations
2. research tournament
3. multi-agent >3 roles
4. counterfactual sensitivity variants
5. cross-investigation intelligence
6. dynamic graphs

Never cut:

- evidence/inference separation
- blocker integrity
- persistence truth
- original source preservation
- no raw AI mutation
- verification distinction
- secrets safety

## Parallelization

If multiple agents can work independently after core contracts exist:

Agent A:
Domain + tests.

Agent B:
Workspace + Forma.

Agent C:
Persistence + offline.

Agent D:
AI + tool/context layer.

ROS/semantic compiler prevents drift.

## Branch strategy

Use short-lived branches/worktrees if tooling supports rapid integration.

Every branch must target a defined work item and acceptance evidence.

Avoid long-lived parallel architecture divergence.

## Build-day metrics

Track:

- elapsed time per slice
- agent/model cost
- build/test count
- semantic contract completeness
- requirement coverage
- repeated file churn
- Aegis faults
- retries/rework

## Success

A strong result at 5 PM is not "everything in the requirements exists."

It is:

- the core thesis works end-to-end
- the factory is visible and reusable
- advanced feature proves the architecture buys something
- security/testing/observability are evidenced
- incomplete work is honestly classified
